# MNT02 M10 — AI 기반 야전 정비 부품 수요예측 및 재고최적화 시스템 통합 패키지 완성

## 상황과 목표

가상 부품 데이터 분석 담당자로서 수요·단종 상태·재고 근거를 분석합니다. 수요 예측, 재학습, 안전재고·위험 지수, 단종 대응, 발주 추천과 결재 대기열을 한 번에 실행하는 통합 패키지를 완성한다.

## 원본 수행 범위와 평가

- 원본 필수 미션. 전체 실습에서는 수행합니다.
- 원본·새 Git 편성 3.5시간〔실측값이 아님〕
- 원본 수행: 자료 생성·정합성 점검, 운영 모델과 재학습 모델 비교 후 교체 판단, 다음 달 예측과 위험 지수 산출을 한 흐름으로 실행한다. 단종예고 품목은 최종 구매(LTB) 수량을, 단종 품목은 대체품 보유 여부를 정리하고 생산중 품목은 예산 제약 발주를 추천해 결재 대기열에 올린다. 운영 가이드 10개 장과 가상 연계 메시지 규격, 자체 점검표, 브리핑 요약을 출력한다.
- [필수] 통합 패키지  — 재학습 파이프라인 정상 실행과 교체 판단, 자체 점검 전 항목 PASS, 운영 가이드 완비율 100%, 브리핑 수치가 실행 결과와 일치하는가.
- 원본 산출물: docs/mnt02_operations_guide.md 및 pipeline/mnt02_retrain.py, 브리핑 요약

## 제공 자료

- 공통 작성 안내·Colab 실행 안내·실습 노트북·실습프로젝트 ZIP.
- 코드: `pipeline/mnt02_retrain.py`. 핵심 함수를 구현·저장하고 첫 실행 후 AI와 추가 변경합니다.
- 데이터: 프로젝트 `data/README.md`를 먼저 읽습니다.37필드 사전·18필드 원시 자료·21개 모델 입력을 구분합니다.
- 시작 양식: `MNT02_M10_forms.md` 및 docs/reports의 미완성 작성 틀.


## 이번 미션의 핵심 구현

- 파일: `pipeline/mnt02_retrain.py`
- 함수: `choose_version`
- 계약: 운영모델 오차e1,후보모델 오차e2 → v1/v2 문자열. 유한한0이상 오차만 비교하고 e2<=e1이면 v2를 선택한다. 빈/NaN 평가를 거부하고 실제 선택 모델로 이후 예측한다.
- 반복 데이터 생성 함수는 제공 코드입니다. M1의 check는 제공하고 validate를 구현합니다.
- 핵심 구현 후 첫 성공 실행을 보존하고 기존 추가 변경 과제를 수행해 전후 비교합니다. 실제 AI 대화·본인 근거 검토·오류 수정 이유를 남깁니다.

## 학습 활동

### 활동1 — 계획과 사전 판단

원본 목표·기본 코드·자료를 읽고 운영 모델 유지/교체와 실제 다음달 예측을 어떻게 연결할까?를 판단합니다. AI에 맡길 범위·자료·제약·확인 방법을 정합니다.

### 활동2 — AI와 코드 변경

핵심 함수를 구현하고 첫 실행 결과를 보존한 뒤 AI와 기획을 구현에 적용합니다. 변경 과제: LTB_MONTHS24→12 변경을 비교하고 선택된 모델·대기열·직접 작성 10장 문서·브리핑 수치를 대조한다.

### 활동3 — 근거 대조와 재실행

수정 코드를 저장하고 재실행합니다. 선택 모델·대기열·10장 본문·실행 출력·브리핑이일치하는가? AI 설명·코드 선택3건 이상을 자료·실행과 대조하고 보완 답변도 다시 확인합니다.

### 활동4 — 최종 판단과 산출물

원본 평가 기준·변경 전후·코드·실제 AI 대화·보고서를 제출합니다. 미달·미측정·실제 승인 상태를 구분합니다. M10의t42~47은모델 선택 구간이며독립 최종 평가가 아닙니다. 원본에서는v1 유지 후전체 학습 모델로예측하는 불일치가 있어실제 선택v1/v2로예측하도록 고쳤습니다. 가상 2026-01 실제 수요는미제공입니다. 가이드 10문장 출력은 10장 본문 작성이 아니며 시작문서는FAIL입니다. 실제 문서 작성·직접 승인·교관 검토는별도입니다.
