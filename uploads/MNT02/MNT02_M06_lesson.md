# MNT02 M06 — 야전 부품 재고 현황 및 긴급 조달 필요 품목 가시화 대시보드 구현

## 상황과 목표

가상 부품 데이터 분석 담당자로서 수요·단종 상태·재고 근거를 분석합니다. 야전 부품 재고 현황과 긴급 조달 필요 품목을 보여 주는 대시보드를 만들고 품목별 위험 원인을 설명한다.

## 원본 수행 범위와 평가

- 원본 선택 미션. 전체 실습에서는 수행합니다.
- 원본·새 Git 편성 3시간〔실측값이 아님〕
- 원본 수행: 가용재고와 재주문점, 품목군·생산 상태별 위험 지수, 긴급 조달 필요 품목을 그림으로 표시한다. 리드타임·수요 증가·재고 부족·예측 불확실성·단종 상태·단일 공급업체·대체품 부재를 하나씩 기준값으로 바꿔 위험 지수 변화를 계산하고 기여도 상위 3개 인자를 뽑는다. '주된 원인은 조달 리드타임이 길다'처럼 자연어 설명문을 자동 생성한다.
- [선택] 재고 대시보드·설명  — 품목별 기여도 상위 3개 인자 자동 산출률 100%, 긴급 조달 품목별 자연어 설명 생성, 생산 상태별 위험 차이를 제시했는가.
- 원본 산출물: src/explainability/mnt02_xai_explainer.py 및 XAI 리포트, 대시보드 화면

## 제공 자료

- 공통 작성 안내·Colab 실행 안내·실습 노트북·실습프로젝트 ZIP.
- 코드: `src/explainability/mnt02_xai_explainer.py`. 핵심 함수를 구현·저장하고 첫 실행 후 AI와 추가 변경합니다.
- 데이터: 프로젝트 `data/README.md`를 먼저 읽습니다.37필드 사전·18필드 원시 자료·21개 모델 입력을 구분합니다.
- 시작 양식: `MNT02_M06_forms.md` 및 docs/reports의 미완성 작성 틀.


## 이번 미션의 핵심 구현

- 파일: `src/explainability/mnt02_xai_explainer.py`
- 함수: `explain`
- 계약: iid → 위험 지수와 상위3개 모델 민감도 요인을 설명하는 문자열. 제공 dash/top3/C/CAUSE를 사용하며 실제 고장 원인·인과를 확정하지 않는다.
- 반복 데이터 생성 함수는 제공 코드입니다. M1의 check는 제공하고 validate를 구현합니다.
- 핵심 구현 후 첫 성공 실행을 보존하고 기존 추가 변경 과제를 수행해 전후 비교합니다. 실제 AI 대화·본인 근거 검토·오류 수정 이유를 남깁니다.

## 학습 활동

### 활동1 — 계획과 사전 판단

원본 목표·기본 코드·자료를 읽고 설명에서확인할 수 있는 것은모델 변화인가실제 원인인가?를 판단합니다. AI에 맡길 범위·자료·제약·확인 방법을 정합니다.

### 활동2 — AI와 코드 변경

핵심 함수를 구현하고 첫 실행 결과를 보존한 뒤 AI와 기획을 구현에 적용합니다. 변경 과제: 위험 60/70 기준의 목록과 설명을 비교하며 요인별 일회 대조 결과가 가법적 설명인지·인과 주장인지 검토한다.

### 활동3 — 근거 대조와 재실행

수정 코드를 저장하고 재실행합니다. 상위 3개·긴급 목록·정적 화면과설명이같은 결과를 사용했는가? AI 설명·코드 선택3건 이상을 자료·실행과 대조하고 보완 답변도 다시 확인합니다.

### 활동4 — 최종 판단과 산출물

원본 평가 기준·변경 전후·코드·실제 AI 대화·보고서를 제출합니다. 미달·미측정·실제 승인 상태를 구분합니다. 요인 1개 씩 기준값으로 대조한 변화는 개별 모델 민감도입니다. 합이 원점수와 같거나 요인의 실제 인과 기여라고 보장하지 않습니다. 상위 3개 산출률과 설명의 정확성을 따로 확인합니다. 대시보드는정적 그림이며실시간 웹서비스가 아닙니다.
