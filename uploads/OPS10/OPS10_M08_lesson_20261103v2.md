# OPS10 미션8 AAR 디브리핑을 통한 시스템적 결함 및 휴먼 에러 근본 원인 도출

## 시작과 작성 위치

계획과 기록이 어떻게 다른지 살펴보고 절차를 개선합니다. 사실·진술·원인 가설을 구분하고, AI가 제시한 개선안을 원기록과 비교합니다.

**용어:** AAR는 계획·실제·차이의 원인·개선을 돌아보는 사후 검토입니다. 가설은 아직 확인하지 못한 원인 추정입니다.

**열 자료:** 이 미션 안내의 제공 자료와 학생용 Workbook 미션8. **작성할 곳:** 미션8의 결과 작성란 또는 forms/OPS10_M08_forms.md 한 곳입니다. 최종 문서 경로는 aar/ops10_aar_session_minutes.md이며 도구가 저장합니다. 코드나 폴더를 직접 만들 필요는 없습니다.

## 미션 상황

당신은 교육용 가상 상황실의 훈련 참여자입니다. AAR 디브리핑으로 오경보·지연·누락의 시스템적 결함과 휴먼 에러의 근본 원인을 사실 중심으로 도출한다. 개인 실습에서는 최종 판단을 맡고 AI의 다른 역할과 직접 확인·보고·인계를 주고받습니다.

- 자료의 예상 시간: 3시간〔실측값이 아님〕
- 최종 제출 파일: `aar/ops10_aar_session_minutes.md`
- 공통 작성 안내와 AI 역할 실습 안내를 먼저 읽습니다. 본문의 양식은 설명용이며 작성은 forms 복사본 한 곳에서 합니다.

## 진행할 때 확인하세요

F1~F8은 **원본이 제공한 가상 연습용 발췌**입니다. 본인의 미션4~미션7 실측 결과로 바꾸어 부르지 않습니다. 본인의 실행 기록이 있으면 별도 행에 출처를 적고 분석합니다. F2 진술이 있어도 ‘SOP에 없었다’는 판단은 해당 SOP 버전과 대조해야 합니다. 각 발췌에서 원인을 확정할 자료가 충분한지 직접 판단합니다.

AI를 AAR 진행자 또는 다른 역할의 모의 응답자로 사용하되 근거에 없는 기억·의도·책임을 만들어 내지 못하도록 요청합니다. 본인이 먼저 계획·실제 차이를 고르고, AI의 원인 가설을 검토해 ‘확인된 원인 / 가능성 있는 원인 / 추가 확인 필요’로 구분합니다.

| 기록 출처 | 확인된 현상 | 원인 가설 | 확인한 자료와 범위 | 확정 여부·추가 확인 | SOP 수정 내용 |
| --- | --- | --- | --- | --- | --- |
| | | | | | |

개선 5개 이상을 현행 문장→수정 문장→근거로 연결합니다. 가상 연습 자료의 개선안을 본인 실제 성과가 이미 개선된 것처럼 쓰지 않습니다. 수정 SOP 버전을 미션9에 전달합니다.
