# STR01 M07 — 결핍 부대 긴급 물자 전환 결정을 위한 군수처장 HITL 승인 워크플로우 설계

## 상황과 목표

가상 KPI 분석 담당자로서 부대별 재고·소모·목표 DOS와 결핍 경보를 분석합니다. 예측 기반 보급 정책의 효과를 시뮬레이션으로 비교하고, 결핍 부대에 대한 긴급 물자 전환은 군수처장 승인으로만 집행하는 HITL 워크플로우를 설계한다.

## 원본 수행 범위와 평가

- 원본 필수 미션. 전체 실습에서는 수행합니다.
- 원본·새 Git 편성 3.5시간〔실측값이 아님〕
- 원본 수행: 고정 목표 재고 정책과 예측 기반 동적 목표 정책을 같은 50일 자료로 재현해 결핍량, 재고 회전, 비용을 비교한다. 경계 이하 부대에 다음 보급일까지 버틸 물량을 여유 부대에서 옮기거나 보급소 예비로 충당하는 제안을 만들고, 군수처장의 승인·반려와 결정 근거 기재를 거쳐야만 집행하게 한다. 자동 승인, 권한 없는 승인 등 우회 시도를 차단하고 감사 이력을 해시로 검증한다.
- [필수] 정책 시뮬레이션·군수처장 HITL  — 최적화 적용 시 비용 15% 절감 또는 재고 회전율 20% 향상을 보이고, 군수 제약(보급 주기, 안전 재고 유지)과 시나리오별 대안이 적절하게 반영되며 자동 집행이 없는가.
- 원본 산출물: src/optimization/str01_simulator.py

## 이번 미션의 핵심 구현

- 파일: `src/optimization/str01_simulator.py`
- 함수: `simulate`
- 계약: policy,d_b=6.5 → 정책 시뮬레이션 집계 사전. A 고정/B 동적 목표를 동일50일 자료·4일 주기·가상 비용으로 비교한다. 잘못된 정책·유효하지 않은 d_b는 거부하고0분모는 산출불가다. 실제 물자 이동은 실행하지 않는다.
- 반복 데이터 생성 함수는 제공 코드입니다. 제공 상수·필드 정의를 참조해 M1의 validate_ledger를 구현합니다.
- 핵심 구현 후 첫 성공 실행을 보존하고 기존 추가 변경 과제를 수행해 전후 비교합니다. 실제 AI 대화·본인 근거 검토·오류 수정 이유를 남깁니다.

## 학습 활동

### 활동1 — 계획과 사전 판단

원본 목표·기본 코드·자료를 읽고 비용 절감에도 결핍이 늘면 어떤 정책을 선택할까?를 판단합니다. AI에 맡길 범위·자료·제약·확인 방법을 정합니다.

### 활동2 — AI와 코드 변경

기준 코드를 실행하고 결과를 보존한 뒤 AI와 기획을 구현에 적용합니다. 변경 과제: 동적 목표 일수 d_b를 6.5에서 5.0으로 바꿔 비용·결핍·회전을 비교합니다. 별도 직접 입력 도구로 제안 3건 이상을 승인·반려·보류하고 근거를 남깁니다. 집행은 연결하지 않습니다.

### 활동3 — 근거 대조와 재실행

수정 코드를 저장하고 재실행합니다. AI 자동 결정·권한 없는 결정·무사유·중복 결정·자원 초과를 차단했는가? AI 설명·코드 선택3건 이상을 자료·실행과 대조하고 보완 답변도 다시 확인합니다.

### 활동4 — 최종 판단과 산출물

원본 평가 기준·변경 전후 코드·실제 AI 대화·보고서를 제출합니다. 정량 달성, 미측정, 문서 작성과 교관 승인 상태를 구분해 최종 판단을 남깁니다.

## 해석·검증 주의점

50일 동일 자료로 고정/동적 정책을 비교합니다. 서로 다른 품목 수량을 합친 회전은 원본의 상대 지표이며 회계상 회전율이 아닙니다. 단가는 가정이고 예측 오류·결핍·재고 상충을 함께 봅니다. 참고 코드의 SIMULATED 결정은 학습자 직접 입력과 다릅니다. 직접 입력은 군수처장 가상 역할이며 실제 인증·물자 이동이 아닙니다. 제안 시 자원을 예약하는 보수적 모형이므로 반려 후 자원을 자동 재배정하지 않습니다. 해시는 내부 변경 검사이고 외부 신뢰 기준점 없이 로그 전체 재작성은 막지 못합니다.
