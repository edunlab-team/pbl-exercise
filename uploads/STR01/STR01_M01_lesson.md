# STR01 M01 — 부대별 5대 핵심 보급품(식량, 피복, 유류, 탄약, 수리부속) 재고 및 기준 보급일수(DOS) 스키마 정의

## 상황과 목표

가상 KPI 분석 담당자로서 부대별 재고·소모·목표 DOS와 결핍 경보를 분석합니다. 5대 핵심 보급품(식량, 피복, 유류, 탄약, 수리부속)의 재고와 기준 보급일수(DOS) 핵심성과지표(KPI)의 스키마와 데이터 딕셔너리를 정의하고 KPI 보고 업무 프로세스 맵을 작성한다.

## 원본 수행 범위와 평가

- 원본 필수 미션. 전체 실습에서는 수행합니다.
- 원본·새 Git 편성 1.5시간〔실측값이 아님〕
- 원본 수행: 교육용 가상 부대 20개의 일일 재고·소모·보급 원장을 만들어 필드, 형식, 허용값, 의미를 데이터 딕셔너리로 정리한다. DOS = 재고 / 최근 7일 평균 소모량, 목표 대비 편차와 달성률을 KPI로 정의하고, 분석에 쓸 피처 목록을 20개 이상 만든다. 부대 보고 수신부터 처장 승인까지 현행 KPI 보고 업무를 11단계로 그려 AS-IS/TO-BE 소요시간을 비교한다.
- [필수] 스키마·프로세스 맵  — 업무 프로세스 맵이 작성 완료되고 피처 목록 20개 이상이 정의되었으며, 군수 실무 프로세스와 일치하고 분석 목표가 명확한가.
- 원본 산출물: docs/str01_logistics_domain_spec.md 및 데이터 딕셔너리

## 이번 미션의 핵심 구현

- 파일: `src/domain/str01_domain.py`
- 함수: `validate_ledger`
- 계약: 원장 frame(DataFrame) → 검사 항목별 참/거짓 사전. 필수9필드·결측·유한값·부대/품목·일자 범위/정수·기상 이진·음수·중복·160일 연속·100개 키를 검사한다. 제공 UNITS·ITEMS·DAYS·N_UNIT을 사용한다. 필수 열 누락은 필수 필드=False로 반환하고 제공 자료 범위를 넘는 승인·실제 업무 적합성을 확정하지 않는다.
- 반복 데이터 생성 함수는 제공 코드입니다. 제공 상수·필드 정의를 참조해 M1의 validate_ledger를 구현합니다.
- 핵심 구현 후 첫 성공 실행을 보존하고 기존 추가 변경 과제를 수행해 전후 비교합니다. 실제 AI 대화·본인 근거 검토·오류 수정 이유를 남깁니다.

## 학습 활동

### 활동1 — 계획과 사전 판단

원본 목표·기본 코드·자료를 읽고 DOS 분모가 0이거나 재고 0일 때 각각 어떻게 표시할까?를 판단합니다. AI에 맡길 범위·자료·제약·확인 방법을 정합니다.

### 활동2 — AI와 코드 변경

기준 코드를 실행하고 결과를 보존한 뒤 AI와 기획을 구현에 적용합니다. 변경 과제: 목표 DOS를 품목 하나에서 바꿔 KPI 편차·달성률을 전후 비교합니다. 평균 소모가 0일 때 DOS를 임의의 큰 수로 표시하지 않는 처리 규칙을 AI와 구현하고 경계 사례로 검증합니다.

### 활동3 — 근거 대조와 재실행

수정 코드를 저장하고 재실행합니다. 피처 후보 24개 중 실제 자동 산출과 미구현 후보를 나눴는가? AI 설명·코드 선택3건 이상을 자료·실행과 대조하고 보완 답변도 다시 확인합니다.

### 활동4 — 최종 판단과 산출물

원본 평가 기준·변경 전후 코드·실제 AI 대화·보고서를 제출합니다. 정량 달성, 미측정, 문서 작성과 교관 승인 상태를 구분해 최종 판단을 남깁니다.

## 해석·검증 주의점

원장 9개 필드와 딕셔너리 11개〔target_dos·dos 포함〕, 피처 후보 24개〔자동 16개+추가 후보 8개〕를 구분합니다. 추가 후보는 실제 구현된 입력 8개라는 뜻이 아닙니다. 프로세스 11단계와 535→34분은 교육용 가정입니다. DOS는 일 단위이고 목표 달성률은 비율입니다. 소모 0이면 DOS 산출 불가 사유를 표시하고 이미 재고 0은 별도 관찰 경보로 처리합니다.
