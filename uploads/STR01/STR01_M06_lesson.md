# STR01 M06 — 군단/사단 관할 부대 보급 수준(DOS) 실시간 현황 지도 및 경보 대시보드 구현

## 상황과 목표

가상 KPI 분석 담당자로서 부대별 재고·소모·목표 DOS와 결핍 경보를 분석합니다. 관할 부대의 DOS 현황을 가상 지도와 경보 색상으로 보여 주는 대시보드를 구현하고, 경보마다 예측에 기여한 인자를 설명한다.

## 원본 수행 범위와 평가

- 원본 선택 미션. 전체 실습에서는 수행합니다.
- 원본·새 Git 편성 3시간〔실측값이 아님〕
- 원본 수행: 20개 부대를 격자형 가상 지도에 배치해 부대별 최악 경보 등급을 색으로 표시하고, 3개 시점의 갱신 결과를 출력한다. 경보 건마다 각 피처를 평균값으로 바꿨을 때 예측이 변하는 정도를 계산해 기여도 상위 3개 인자를 자동으로 설명하고, 설명이 실제로 예측에 영향을 주는지 점검한다.
- [선택] 현황 지도·XAI 설명  — 주요 예측 건당 기여도 상위 3개 인자 자동 산출률 100%이며, 군수 장교와 군무원이 신뢰하고 조치할 수 있게 설명이 명확한가.
- 원본 산출물: src/explainability/str01_xai_explainer.py 및 XAI 리포트

## 제공 자료

- 코드: `src/explainability/str01_xai_explainer.py`. 핵심 함수를 구현·저장하고 첫 실행 후 AI와 추가 변경합니다.
- 데이터: 프로젝트 `data/README.md`를 먼저 읽습니다.원장9개 필드·딕셔너리11개 필드·모델 입력16개·추가 후보8개를 구분합니다.
- 시작 양식: `STR01_M06_forms.md` 및 docs/reports의 미완성 작성 틀.


## 이번 미션의 핵심 구현

- 파일: `src/explainability/str01_xai_explainer.py`
- 함수: `explain`
- 계약: row → 예측값과 상위3개 입력 민감도. 평균값 대체로 예측 변화 절댓값을 비교한다. SHAP·인과·실제 결핍 원인으로 단정하지 않는다.
- 반복 데이터 생성 함수는 제공 코드입니다. 제공 상수·필드 정의를 참조해 M1의 validate_ledger를 구현합니다.
- 핵심 구현 후 첫 성공 실행을 보존하고 기존 추가 변경 과제를 수행해 전후 비교합니다. 실제 AI 대화·본인 근거 검토·오류 수정 이유를 남깁니다.

## 학습 활동

### 활동1 — 계획과 사전 판단

원본 목표·기본 코드·자료를 읽고 인자 하나를 평균으로 바꾸는 설명의 한계는 무엇일까?를 판단합니다. AI에 맡길 범위·자료·제약·확인 방법을 정합니다.

### 활동2 — AI와 코드 변경

기준 코드를 실행하고 결과를 보존한 뒤 AI와 기획을 구현에 적용합니다. 변경 과제: 경보 사례 3건에서 상위 인자를 평균값으로 치환하고 변화 방향을 직접 확인합니다. 이미 결핍된 건의 규칙 설명과 예측 경보의 모델 설명을 구분합니다.

### 활동3 — 근거 대조와 재실행

수정 코드를 저장하고 재실행합니다. 이미 재고 0인 품목도 지도에 표시되는가? AI 설명·코드 선택3건 이상을 자료·실행과 대조하고 보완 답변도 다시 확인합니다.

### 활동4 — 최종 판단과 산출물

원본 평가 기준·변경 전후 코드·실제 AI 대화·보고서를 제출합니다. 정량 달성, 미측정, 문서 작성과 교관 승인 상태를 구분해 최종 판단을 남깁니다.

## 해석·검증 주의점

가상 지도는 4×5 격자이며 실제 위치가 아닙니다. 100~102일의 3시점 재생입니다. 이미 재고 0인 품목은 최악 경보에 포함합니다. 상위 3인자 산출률 분모는 양수 재고의 예측 경보이고, 이미 결핍은 재고 관찰 규칙으로 설명합니다. 평균 치환의 예측 변화는 국소 민감도이며 SHAP·인과 효과가 아닙니다. 자동 산출 100%는 설명 품질 검토를 대신하지 않습니다.
