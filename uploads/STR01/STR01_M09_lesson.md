# STR01 M09 — AAR 기반 결핍 경보 지연 원인 분석 및 경보 임계 파라미터 재보정

## 상황과 목표

가상 KPI 분석 담당자로서 부대별 재고·소모·목표 DOS와 결핍 경보를 분석합니다. AAR 사례의 결핍 경보 지연 원인을 분석하고 경보 임계 파라미터를 재보정한다.

## 원본 수행 범위와 평가

- 원본 필수 미션. 전체 실습에서는 수행합니다.
- 원본·새 Git 편성 3시간〔실측값이 아님〕
- 원본 수행: 실제 결핍(재고 0 진입) 사건 48건에 대해 기존 단순 DOS 경보의 정시·지연·미탐을 분류하고 원인을 템포 급변, 추정 오차, 임계 과소로 나눈다. 예측 기반 경보의 임계를 보정 기간에서 격자 탐색으로 정하고 검증 기간에서 확인한다. 비용 절감액, 시간 단축률, 결핍 사건 감소율의 3대 효과 지표를 가정 단가와 산식으로 산출한다.
- [필수] 경보 지연 분석·ROI  — 비용 절감액, 시간 단축률 등 3대 정량 효과 지표를 산출하고, 추정 산식과 가정이 객관적이어서 군 재정·군수 기획 부서를 설득할 수 있는가.
- 원본 산출물: reports/str01_roi_analysis.md

## 이번 미션의 핵심 구현

- 파일: `src/analysis/str01_aar.py`
- 함수: `first_alert`
- 계약: u,it,t_e,th,col → 사건 전 최초 경보일 또는 None.95~110 보정 사건은95일부터,111~125 검증 사건은111일부터 탐색한다. 정답을 알기 전에 이미 저장된 경보 자료만 사용하고 사건일 이후는 보지 않는다.
- 반복 데이터 생성 함수는 제공 코드입니다. 제공 상수·필드 정의를 참조해 M1의 validate_ledger를 구현합니다.
- 핵심 구현 후 첫 성공 실행을 보존하고 기존 추가 변경 과제를 수행해 전후 비교합니다. 실제 AI 대화·본인 근거 검토·오류 수정 이유를 남깁니다.

## 학습 활동

### 활동1 — 계획과 사전 판단

원본 목표·기본 코드·자료를 읽고 보정 기간의 오탐을 계산하는 데 검증 기간 경보를 써도 될까?를 판단합니다. AI에 맡길 범위·자료·제약·확인 방법을 정합니다.

### 활동2 — AI와 코드 변경

기준 코드를 실행하고 결과를 보존한 뒤 AI와 기획을 구현에 적용합니다. 변경 과제: 회피율 AVOID를 70%에서 50%로 바꿔 검증 기간의 추정 효과를 비교합니다. 보정 임계는 보정 기간에서만 선택하고 검증 성능으로 다시 골라 목표를 맞추지 않습니다.

### 활동3 — 근거 대조와 재실행

수정 코드를 저장하고 재실행합니다. 추정 ROI와 실측 업무시간을 구분하고 회피율 민감도를 제시했는가? AI 설명·코드 선택3건 이상을 자료·실행과 대조하고 보완 답변도 다시 확인합니다.

### 활동4 — 최종 판단과 산출물

원본 평가 기준·변경 전후 코드·실제 AI 대화·보고서를 제출합니다. 정량 달성, 미측정, 문서 작성과 교관 승인 상태를 구분해 최종 판단을 남깁니다.

## 해석·검증 주의점

원인 분류는 패턴 기반 가설입니다. 보정 95~110일 사건과 검증 111~125일 사건을 분리하며 보정 오탐 경보는 95~103일로 제한해 이후7일의 관찰이 보정 종료110일을 넘지 않게 합니다. 검증 경보는111~125일로 한정하고132일까지 추적합니다. 임계 적용도111일부터 시작합니다. 오탐은 이후 7일간 실제 재고 0 여부로 판정합니다. ROI는 검증 기간만 사용합니다. 회피율·손실·대응 비용은 가정이며 결핍 감소는 추정치입니다. 선행시간 추가 확보 비율을 업무 처리시간 단축 실측으로 제출하지 않습니다. 처리시간 실측이 없으면 미측정으로 적습니다.
