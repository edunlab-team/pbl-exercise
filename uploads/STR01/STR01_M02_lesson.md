# STR01 M02 — 부대별 일일 소모율 정규화 및 재고 변동 데이터 전처리 모듈 구현

## 상황과 목표

가상 KPI 분석 담당자로서 부대별 재고·소모·목표 DOS와 결핍 경보를 분석합니다. 부대별 일일 소모율을 정규화하고 재고 변동 데이터를 정제하는 전처리 모듈을 구현하며, 군수 특수 예외는 보존한다.

## 원본 수행 범위와 평가

- 원본 필수 미션. 전체 실습에서는 수행합니다.
- 원본·새 Git 편성 2시간〔실측값이 아님〕
- 원본 수행: 중복, 누락 일자, 소모량 결측, 단위 혼용, 음수 재고, 품목명 오타, 태그 없는 이상 급증을 일부러 섞은 가상 원장을 만들어 정제 규칙 10종을 적용한다. 긴급 불출과 비계획 정비로 태그된 급증은 이상치로 깎지 않고 보존한다. 정제 후 정합성 검증 10항목의 통과율과 원본 복원 품질을 정제 품질 보고서로 출력한다.
- [필수] 정제 규칙·특수 예외 보존  — 데이터 정제 규칙 10종을 적용하고 정합성 검증 통과율 100%이며, 긴급 불출·비계획 정비 같은 군수 특수 예외가 삭제되지 않고 보존되는가.
- 원본 산출물: src/etl/str01_data_cleansing.py 및 정제 품질 보고서

## 제공 자료

- 공통 작성 안내·Colab 실행 안내·실습 노트북·실습프로젝트 ZIP.
- 코드: `src/etl/str01_data_cleansing.py`. 핵심 함수를 구현·저장하고 첫 실행 후 AI와 추가 변경합니다.
- 데이터: 프로젝트 `data/README.md`를 먼저 읽습니다.원장9개 필드·딕셔너리11개 필드·모델 입력16개·추가 후보8개를 구분합니다.
- 시작 양식: `STR01_M02_forms.md` 및 docs/reports의 미완성 작성 틀.


## 이번 미션의 핵심 구현

- 파일: `src/etl/str01_data_cleansing.py`
- 함수: `normalize_consumption`
- 계약: 원장 frame,window=14 → base·rate를 추가한 복사본. 부대·품목별 날짜순 첫 window일 소모 중앙값으로 정규화한다. 원본·예외 태그를 보존하고 기준0은 NaN이다. 사후 정제 기준이며 실시간 피처로 쓰지 않는다.
- 반복 데이터 생성 함수는 제공 코드입니다. 제공 상수·필드 정의를 참조해 M1의 validate_ledger를 구현합니다.
- 핵심 구현 후 첫 성공 실행을 보존하고 기존 추가 변경 과제를 수행해 전후 비교합니다. 실제 AI 대화·본인 근거 검토·오류 수정 이유를 남깁니다.

## 학습 활동

### 활동1 — 계획과 사전 판단

원본 목표·기본 코드·자료를 읽고 태그가 있는 급증과 단위 오류를 같은 방식으로 고쳐도 될까?를 판단합니다. AI에 맡길 범위·자료·제약·확인 방법을 정합니다.

### 활동2 — AI와 코드 변경

기준 코드를 실행하고 결과를 보존한 뒤 AI와 기획을 구현에 적용합니다. 변경 과제: R5 상한 배수를 3에서 2로 바꿔 복원 오차와 특수 예외 40건의 값 보존을 비교합니다. 원본을 보존하고 두 실행의 정제 보고서를 따로 저장합니다.

### 활동3 — 근거 대조와 재실행

수정 코드를 저장하고 재실행합니다. 특수 예외 40건의 값과 태그가 모두 보존됐는가? AI 설명·코드 선택3건 이상을 자료·실행과 대조하고 보완 답변도 다시 확인합니다.

### 활동4 — 최종 판단과 산출물

원본 평가 기준·변경 전후 코드·실제 AI 대화·보고서를 제출합니다. 정량 달성, 미측정, 문서 작성과 교관 승인 상태를 구분해 최종 판단을 남깁니다.

## 해석·검증 주의점

규칙 R1~R10은 가상 오염 주입을 전제로 합니다. 기초 재고는 제공된 정답 자료에서 얻는 교육 설정입니다. 실제 원장을 원인 확인 없이 고치지 않습니다. 보간·전체기간 중앙값은 사후 정제이며 예측 입력의 인과 처리와 다릅니다. 100%는 10개 정합성 검사 통과이고 모든 셀의 진실 복원 100%가 아닙니다. 태그 건수와 원래 예외값도 비교합니다.
