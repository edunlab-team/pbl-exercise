# QLT05 M10 — 야전 장비 결함 보고(QDR) 데이터 분석 및 품질 취약점 식별 도구 통합 완성

## 상황과 목표

가상 품질 분석 담당자로서 외주정비 검사 실적과 QDR를 분석합니다. QDR 검증·정제부터 치명도 분류, 취약성 지수·경보, 원인 분류, 승인 대기 후보 제안, 재학습까지 한 파일로 통합하고 자체 점검과 브리핑 요약을 출력하는 도구를 완성한다.

## 원본 수행 범위와 평가

- 원본 필수 미션. 전체 실습에서는 수행합니다.
- 원본 예상 시간 3.5시간〔실측값이 아님〕
- 원본 수행: 지난달·이번 달 실적으로 챔피언 모델과 도전자 모델을 학습해 검증 정확도를 비교하고 비슷하거나 나을 때만 교체한다. 운용 QDR의 손상 서술은 수동 확인으로 분리하고 모델 장애 시 키워드 규칙으로 대체하는 동작을 시험한다. 월별 경보, 취약성 지수 상위 부위, 하자 구상·설계 변경·외주정비 시정 후보(승인 대기)를 만들고 자체 점검, 운영 문서 7개 장 완비 여부, 품질 담당 장교 브리핑 요약을 출력한다.
- [필수] 통합 도구 완성  — 자동 재학습 파이프라인 정상 실행, 최종 문서 100% 완비, 자체 점검 전 항목 통과, 군수 정보체계 연동 인터페이스 방안이 있어 지속 운영이 가능한가.
- 원본 산출물: docs/qlt05_operations_guide.md, pipeline/qlt05_retrain.py

## 제공 자료

- 공통 작성 안내·Colab 실행 안내·실습 노트북·실습프로젝트 ZIP.
- 코드: `pipeline/qlt05_retrain.py`. 핵심 함수를 구현·저장하고 첫 실행 후 AI와 추가 변경합니다.
- 데이터: 프로젝트 `data/README.md`를 먼저 읽습니다.22필드 사전과15필드 원시 자료가 구분되어 있습니다.
- 시작 양식: `QLT05_M10_forms.md` 및 docs/reports의 미완성 작성 틀.

## 이번 미션의 핵심 구현

- 파일: `pipeline/qlt05_retrain.py`
- 함수: `retrain`
- 입력·출력 계약: champion,old,new → (선택 모델, 챔피언/도전자 정확도·교체 여부 사전). 새 월 구간 앞2/3만 학습하고 뒤1/3은 선택 검증으로 남긴다. 빈 구간은 명확히 거부한다.
- 데이터 생성 함수 usage_index는 제공 코드입니다. 반복되는 생성 함수 빈칸 대신 위 핵심 함수를 구현합니다.
- 핵심 구현 후 첫 실행을 기준으로 보존하고, 추가 변경 과제를 수행해 전후를 비교합니다. AI 초안을 그대로 제출하지 말고 실제 대화·본인 검토·오류 수정 근거를 남깁니다.


## 학습 활동

### 활동1 — 계획과 사전 판단

원본 목표·기본 코드·자료를 읽고 더 나쁘지만 허용오차 안인 모델을 교체할 것인가?를 판단합니다. AI에 맡길 범위·자료·제약·확인 방법을 정합니다.

### 활동2 — AI와 코드 변경

핵심 함수를 구현하고 첫 실행 후 결과를 보존한 뒤 AI와 기획을 구현에 적용합니다. 변경 과제: 재학습 허용 오차0.005와0을 비교한다. 시간 순서·교체/유지 이유·장애 대체·후보 대기를 검증하고 운영 가이드7개 장 본문과5분 브리핑을 완성한다.

### 활동3 — 근거 대조와 재실행

수정 코드를 저장하고 재실행합니다. 목차·요약·완비된 운영 본문은 어떻게 다른가? AI 설명·코드 선택3건 이상을 자료·실행과 대조하고 보완 답변도 다시 확인합니다.

### 활동4 — 최종 판단과 산출물

원본 평가 기준·변경 전후·코드·실제 AI 대화·보고서를 제출합니다. 미달·미측정·실제 승인 상태를 구분합니다. 재학습은 단일84개월 시간선으로 보완했다. 기존0~35월, 추가학습36~51월, 선택검증52~59월, 독립 운용60~83월이다. 운용 출력 month는0~23으로 다시 매긴다. tolerance0.005는 정확도0.5%p 감소를 허용한다는 교육용 정책이며 엄격한 무저하 정책은0이다. 운영 요약7줄과 학습자7장 본문 완비를 구분한다. 독립 모듈 실행 도구는 실제 군수 DB/API 연동 구현이 아니다.
