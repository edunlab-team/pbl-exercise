# QLT05 공통 작성 안내

이 프로젝트는 외주정비 품질검사 실적·병목 분석입니다. QDR은 Quality Deficiency Report, 품질결함보고입니다. 외주A~D, 부대정비, MK1~MK4, VU-01~30, VX 장비코드, 서술·비용·검사 실적은 전부 교육용 가상 자료입니다. 원본 해외 사례는 문제 구조를 참고할 뿐 실제 수치·기관 자료를 사용하지 않습니다.

## 실제 수행 순서

1. M01~M10 lesson을 읽고 forms 복사본을 작성합니다. 원본 필수는 M1·M2·M3·M5·M7·M9·M10이며 M4·M6·M8은 선택입니다. 이번 전체 실습에서는10개를 모두 진행합니다.
2. 사전 판단 작성 시점을 ‘AI 답변 보기 전/열람 후’로 표시합니다. AI에 맡길 일·입력 자료·제약·평가 방식을 본인의 말로 설계합니다.
3. 학생용 코드의 핵심 빈 함수를 구현·저장한 뒤 최초 결과를 보존합니다. 제공 보조 코드·입출력 계약을 활용하되 교관 정답을 대신 복사하지 않습니다. 미션별 변경 과제를 AI와 구현하고 수정 코드·실제 대화를 남깁니다.
4. AI 설명이나 코드 선택3개 이상을 원본 자료·계산·실행·테스트와 대조합니다. 맞으면 유지 이유를, 틀리면 수정과 재확인 근거를 기록합니다. AI에게 ‘맞니?’라고 재질문한 답만 검증 근거로 쓰지 않습니다.
5. 동일한 평가 구간·난수시드·분모에서 변경 전후를 비교합니다. 목표 달성·미달·미측정·판정 불가를 구분하고 과제 완료와 교관 승인 상태를 구분합니다.
6. docs/reports의 시작 양식은 아직 작성하지 않은 파일입니다. 본문과 결과를 채웁니다. lesson/forms도 프로젝트 forms에 들어 있으므로 작성본을 저장해 제출합니다.

## 데이터와 시점

data_dictionary.csv는 원본22필드 사전, qdr_36months.csv는 원시15필드, qdr_schema_samples.json은22필드를 조합한20개 표본입니다. M02 원시·정제 CSV와 M07 후보표도 제공합니다. 각 원본 참고 코드는 독립적으로 데이터를 생성합니다. 미션에 따라36·48·60·120개월, seed·scale이 달라 같은 총건수를 기대하면 안 됩니다.

part/sev의 숫자는 PARTS/SEV 목록 인덱스입니다. 텍스트 라벨과 생성기 정답을 구분합니다. cause·sev·event는 합성 정답이어서 사후 검증에 쓰며, 원인/치명도를 예측할 때 정답 열 자체를 입력으로 넣지 않습니다. 수리 비용·실제 원인과 검사가 완료되어야 알 수 있는 정보를 사전 예측에 섞지 않습니다. 월간 예측은 월말 집계가 확보된 뒤 다음 월을 한 단계 예측하는 모의 실습입니다.

## 평가

Why: AI에 맡긴 업무와 본인의 선택 이유. How: 실제 대화·코드 변경·검증·보완과 재실행. What: 원본 산출물·고정 조건 비교·최종 판단입니다. 원본 정량·정성 기준을 미션별로 확인합니다. 기준0·빈 평가 집합·미측정은 이유와 함께 판정 불가로 둡니다.

원본 예상 시간은 28.5시간, CMS 정수 편성은 31시간입니다. 실제 학습자 소요 시간은 측정하지 않았습니다. 제작 환경의 코드 실행 시간과 학습 시간이 같지 않습니다.

## 사람의 판단과 보안

AI와 모델은 취약점 후보를 제시합니다. 하자 구상·설계 변경·외주정비 시정은 품질관 결정이 필요한 것으로 유지합니다. 가상 품질관 역할의 직접 입력과 코드가 생성한 모의 승인, 실제 승인 기록을 구분합니다. 실제 부대 촬영·자료 외부 AI 입력·실제 업체 제재·실제 군수체계 연결은 이 교육용 실습에 포함하지 않습니다.


## 시작과 작성·이어쓰기

1. 최신 통합 학생 Notebook과 실습 ZIP을 내려받습니다. Notebook은 미션1~10을 포함하며 미션별 정답 Notebook이 아닙니다.
2. Colab에서 Notebook을 업로드해 엽니다. 준비 셀에서 실습 ZIP 하나를 고르고 ROOT 위치와 라이브러리 버전을 확인합니다. 한글 파일명·중복 다운로드 번호도 처리합니다.
3. lesson을 읽고 해당 함수의 입력·출력 계약을 확인합니다. AI에게 필요한 가상 자료와 빈 함수만 붙여 질문하고, 구현 저장 셀에 전체 def를 넣습니다. 미구현 오류는 함수를 완성하라는 안내입니다.
4. 왼쪽 파일 패널에서 forms의 해당 미션 양식과 docs/reports 문서를 열어 작성·저장합니다. AI 실제 요청·답변은 원문 파일로 남기고 양식에 경로를 적습니다. 각 질문 예시는 본인 과제에 맞춰 바꾸어 씁니다.
5. 첫 실행과 수정 실행은 outputs의 서로 다른 폴더에 남습니다. 저장 도구는 이전 코드를 .before로 보존합니다. 준비 셀을 다시 실행해도 기존 작업을 덮어쓰지 않습니다. 새 버전으로 시작하려면 먼저 기존 결과 ZIP을 보관하고 새 폴더에서 시작합니다.
6. 제출 셀은 미구현·실행 누락·직접 검토 누락을 확인한 뒤 QLT05.zip을 만듭니다. 파일 존재 검사는 내용 완비나 정량 목표 달성 검사가 아닙니다. 엄격한 제출 검사가 막히면 먼저 미완료 부분을 해결하고, 작성 중 사본은 별도 검토용 ZIP 셀로 보관할 수 있습니다.

## 용어와 AI 사용

QDR은 품질결함보고, 스키마는 기록 구조, 필드는 표의 열, 피처는 분석 특징입니다. Baseline은 비교용 기준 방법, hold-out은 학습에서 제외한 평가 구간, AAR은 수행 후 기록 검토입니다. HITL은 사람의 검토를 남기는 과정입니다. 파이썬·표 데이터 기초는 필요하지만 실제 군수 규정 지식은 요구하지 않습니다.

미션별 AI 질문 예시와 가상 자료를 함께 사용합니다. 주장 또는 코드 선택 3건 이상을 원문·테스트·실행값과 대조해 유지·수정·보류 이유를 적습니다. 목표값에 맞추려고 기간·분모·라벨·실행값을 바꾸지 않습니다.

## 환경·자료 구분

Colab과 외부 AI에는 인터넷 연결이 필요합니다. 폐쇄망은 운영기관이 허용한 Python·패키지·AI 환경을 준비해야 합니다. 실제 Colab·폐쇄망 실행과 로컬 검증을 구분합니다. 학생용 파일에는 교관 해답을 넣지 않습니다. 확보하지 못한 Solution은 검증 완료로 표시하지 않습니다. 제공 입력의 합성 라벨은 학습·평가 자료이며 현재 예측의 입력에 섞지 않습니다.
