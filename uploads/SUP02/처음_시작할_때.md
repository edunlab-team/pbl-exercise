# SUP02 — 물자 시효성 품목 재고통제·잔여일 관리

[교육용가상자료] 코드가 가상 조직 U1~U6의 장비 운용시간·환경·정비 이력과 시효성 키트 로트를 생성한다. 실제 조직·장비·재고 자료 없이 미션별로 독립 실행한다.

## 시작
학습자는 01_학습자자료 최상위의 SUP02_assignment.ipynb를 교육장 Jupyter에서 열고 다른 이름으로 저장한 뒤 환경 셀부터 실행합니다. ZIP을 교육장 PC의 허용된 폴더에 풉니다. 노트북의 환경 준비 셀도 필요한 파일을 준비합니다.
로컬: 관리자가 준비한 Python 3.12 Jupyter에서 노트북 열기 → 환경 준비 셀 실행(requirements.txt·src/·reports/ 생성) → 미션 1 코드 저장 셀 실행 → 미션 1 실행·확인 셀 순서로 진행합니다. 이미 고정 라이브러리가 준비된 환경은 설치하지 않습니다. ZIP에는 requirements.txt가 이미 있습니다. 노트북만 새 환경에 열면 환경 셀이 같은 파일을 생성합니다. CLI는 코드 저장 후 `python src/learning_support.py 1 run`, `python src/learning_support.py 1 check`를 사용합니다.

## 수행
원문 이름의 Python 파일은 비교용 보존본입니다. 현재 실행할 수정 파일은 제출 경로 연결표에서 확인하세요. 미션 10도 원문대로 독립 통합 예제이며 앞 미션 코드 파일을 import하는 시스템이라고 주장하지 않습니다.
기본 결과 → 도전 과제(코드 수정·재실행·전후 비교와 해석) → reports 기록지 → 원문 산출물을 완성합니다. 기본 확인 PASS는 학습 완료 판정이 아닙니다. 수정 실습은 실제 운영 문서의 본문과 필수 절을 점검합니다. 빈 양식은 완료가 아닙니다. 원문 산출물 문서는 직접 작성합니다. 미션 8은 최소 로컬 웹앱과 제약 환경용 시뮬레이터를 제공합니다. 공개 웹서비스 배포는 요구하지 않습니다. 예시 숫자·이번 실행 숫자·목표 달성을 구분합니다. 도전 결과가 그대로여도 적용 증거와 이유가 있으면 인정합니다.

outputs에는 실제 실행 로그와 그래프가 생성됩니다. 노트북과 작업 파일을 함께 저장하고 다시 열어 확인합니다. 새 작업 환경에서는 환경 준비 후 저장 사본을 reports/docs/work/outputs 원경로에 복원하고 마지막 작성 기록·미션·실행일시를 확인한 다음 이어 실행합니다. 자세한 순서는 03_참고자료/저장과_새런타임_복원.md를 읽습니다.

## 막혔을 때
`ModuleNotFoundError`는 환경 셀을 실행하고, 경로 오류는 환경 셀과 해당 코드 저장 셀을 실행합니다. 실행 중 표시가 끝날 때까지 기다립니다. 로그의 의도적 오류 검출은 Python 예외와 다릅니다.
교육장 Jupyter에서 같은 노트북을 사용합니다. 권한·보안 제한을 우회하지 않습니다.

DTC=고장 진단 코드, RUL=잔여 수명, MAE=평균 절대오차, RMSE=제곱평균제곱근오차, HITL=사람 확인 단계, AAR=사후 검토.

## 저장과 새 작업 환경 복원

1. 종료 전 수정한 노트북과 `reports/`, 직접 작성한 `docs/`, `work/`, `outputs/`를 원래 폴더 구조 그대로 허용된 저장 매체에 복사합니다. `reports/재개기록.md`에 마지막 미션, 마지막 실행일시, 마지막 작성 문장, 이어 할 일을 직접 적습니다. 노트북 사본과 reports/docs/work/outputs 파일을 함께 저장합니다.
2. 새 작업폴더에서 저장한 노트북을 열고 **환경 준비 셀부터 실행**합니다. 이때 생긴 빈 양식은 저장 기록의 복원이 아닙니다.
3. 저장 사본을 **reports/docs/work/outputs 원경로에 복원**합니다. 예: 저장한 `reports/m01_record.md` → 새 작업폴더의 `reports/m01_record.md`. 파일을 최상위에만 올리지 않습니다. Jupyter 작업폴더의 같은 하위 경로로 복사합니다. 기존 파일이 있으면 별도 보관 후 복원합니다.
4. `reports/재개기록.md`와 마지막 기록지를 열어 **마지막 미션·실행일시·작성 문장**이 저장 사본과 같은지 확인합니다. outputs의 execution.json 시간도 대조합니다. 없으면 진행을 멈추고 저장 사본부터 확인합니다.
5. 이어 할 미션의 코드 저장·실행 셀을 선택합니다. 복원한 work 코드를 다시 쓸 때는 노트북 셀에도 같은 수정 내용을 반영하고 백업 셀을 먼저 실행합니다. 처음부터 모두 실행해 복원 코드를 기본값으로 덮지 않습니다. 같은 분석을 재실행하면 이전 로그는 outputs/history에 남고 새 로그의 실행일시만 새로 찍힙니다. 재개기록에 직접 적은 이전 일시·마지막 미션은 자동으로 바꾸지 않습니다.

복원 연습: `reports/m01_record.md`에 본인이 정한 표식과 실제 실행일시·마지막 미션 1을 적어 저장 → 새 작업폴더 준비 → 원경로 복원 → 환경 준비 재실행 → 표식과 기록 유지 확인 → 미션 1 실행 후 이전 execution.json이 outputs/history에 남는지 확인합니다. 실제 기관의 저장 허용 여부는 별도로 확인합니다.

## 지표·판정의 뜻
미션 3의 r은 스피어만 순위상관이다. 값 자체의 선형성을 보는 피어슨 상관과 달리, 순위가 함께 증가/감소하는 단조 관계를 측정한다. x=1,2,3, y=1,4,9도 순위가 같아 스피어만=1이다. 절대값이 커도 인과나 좋은 성능을 뜻하지 않는다.
미션 5 안정성의 교육용 임시 기준은 학습과 다른 seed=3 생존 장비 평가셋, 각 환경·가동률 그룹 표본 30대 이상, 그룹 MAE ≤ 전체 MAE×1.30이다. 더 작은 오차는 실패로 보지 않으므로 ±30% 하한은 두지 않는다. 30대 미만은 판정 유보, 기준 초과는 미달 그대로 기록한다. 전체 MAE/RMSE·R2 원문 성능목표와 별도다.
미션 10 운영 문서 검사는 docs/sup02_operations_guide.md의 지정 12개 절에 각각 30자 이상 본문이 있고 TODO·(작성)·미작성·여기에 작성이 없는지를 확인한다. 형식적 채움은 내용 정확성이나 최종 승인 증명이 아니며 채점자가 본문을 검토한다. 빈 양식은 0/12가 정상이다. 재학습 검사는 학습/검증 ID 분리, 예측 길이·유한값, MAE 재계산, 승격 문턱, 선택 모델 연결을 실제 대조한다.

## 과제 범위와 FEFO 연결
과제명은 시효성 재고통제이나 원문 미션은 장비 수명·3단계 정비 분석 중심이다. 이 실습에서 재고통제로 연결되는 범위는 미션 5의 시효성 정비 키트 로트 배정, 미션 6 일정, 미션 9 비용, 미션 10 통합 계획이다. 일반 물자의 입출고·재주문·전체 재고통제를 완성한 것으로 해석하지 않는다.
FEFO는 만료가 빠른 로트부터 쓰되 `만료일 ≥ 정비예정일 + KIT_MARGIN`을 만족하는 재고만 배정한다. 미션 5의 LOTS(수량, 만료일), KIT_MARGIN, kit_fefo를 읽고 정비일→유효 로트→재고 차감→부족/잔여·만료 수량을 연결해 기록한다. 예: 정비일 60일, 코드의 KIT_MARGIN=14일이면 만료70일 로트는 제외하고 만료80일 로트를 먼저 고려한다. 이 예시는 코드 실측값이 아니다. 이 실습은 장비 잔여수명 예측과 정비용 키트 배정을 다룬다. 일반 품목의 재고통제 전체를 다루지는 않는다.

원문 소요시간(총 28.5시간)을 유지한다. 초보자는 환경·용어·기록·도전 해석 때문에 원문보다 더 걸릴 수 있으므로 분할 수행하고 실제 소요시간을 기록한다. 추가 시간은 실측되지 않은 안내이며 성과 보장이 아니다.
