# QLT02 M01 군수품 수입/수령 검사 불량 기록(규격 미달, 치수 오차, 외관 결함) 데이터셋 정의

당신은 교육용 품질 데이터 분석 담당자입니다. 군수품 수입·수령 검사 불량 기록(규격 미달, 치수 오차, 외관 결함)을 구매요구-계약-납품-검사 흐름에 맞춰 데이터셋으로 정의한다.

## 원본 기준

- 목표: 군수품 수입·수령 검사 불량 기록(규격 미달, 치수 오차, 외관 결함)을 구매요구-계약-납품-검사 흐름에 맞춰 데이터셋으로 정의한다.
- 원본 예상 1.5시간〔CMS 편성 2시간, 실측 시간이 아님〕
- 수행: 업무 프로세스 맵(구매요구, 계약, 납품, 수령검사, 불출·사용, 사후 확정)을 그리고 단계별로 생기는 데이터를 정리한다. 로트 번호, 업체, 가상 FSC·NIIN 코드, 규격 등급, 납기, 표본 수, 유형별 불량 수, 치수 편차 등 20개 이상 필드의 형식·허용값을 데이터 딕셔너리로 만든다. 교차검증 규칙(불량 유형 합 일치 등)으로 가상 샘플을 검증한다.
- 원본 평가: [필수] 도메인 분석·데이터 정의  — 업무 프로세스 맵 작성, 피처(필드) 20개 이상 정의, 국방 표준 코드 형식(FSC·NIIN) 반영, 분석 목표가 한 문장으로 명확히 제시되었는가.
- 산출물: `docs/qlt02_logistics_domain_spec.md`, `data/data_dictionary.csv`

## 제공 자료와 코드

교육용 기본 코드 `src/domain/qlt02_domain.py`와 공통 데이터 파일을 제공합니다. 핵심 함수는 학습자가 구현할 빈칸이며 나머지는 교육용 제공 도구입니다. 이 ZIP에는 source_originals 폴더나 교관 정답이 포함되어 있지 않습니다. 데이터 딕셔너리와 입력 예시는 실습프로젝트 data 폴더에 있습니다. 가상 데이터 생성식은 교육용 제공 도구입니다.

- 원본 가이드의 진행: 1) M1 코드를 실행해 업무 프로세스 맵 6단계와 단계별 생성 데이터를 확인한다.
2) 데이터 딕셔너리에서 필드별 형식·허용값과 가상 FSC·NIIN 형식을 확인한다.
3) 교차검증 규칙으로 걸러진 오류 샘플을 확인한다.
- 실제 성과값은 본인이 코드를 실행한 뒤 기록합니다. 미리 제시된 예시 수치를 본인 결과로 복사하지 않습니다.

## 출제자가 보완한 판단 기준

원본 필드명 niin은 FSC를 포함한 4-2-3-4 형식의 가상 재고번호를 담습니다. NIIN 부분 9자리와 전체 13자리를 구분해 설명하고 기존 필드명은 유지합니다. 숫자 모양을 본뜬 교육용 코드이며 실제 유효한 국방 코드라는 뜻은 아닙니다. 목표 변수 confirmed_rate와 bad_lot, 사후 field_claims는 현재 로트 예측의 입력으로 사용하지 않습니다. 수령검사 시점의 경보와 입고 전 샘플링 계획을 구분합니다.

## 이번 미션의 구현 범위

- 파일: `src/domain/qlt02_domain.py`
- 구현할 함수: `validate`
- 입력·출력 계약: rec 사전 → 오류 문자열 목록. SCHEMA와 CROSS_RULES를 적용하고 누락·자료형·범위·교차 오류를 구분한다.
- 데이터 생성·공통 보조 함수는 제공 코드입니다. 반복되는 생성 함수 빈칸을 채우는 활동으로 대체하지 않습니다.
- 먼저 핵심 함수를 구현해 첫 실행 결과를 확보하고, 아래 변경 과제로 수정 전후를 비교합니다. 실제 AI 요청·답변과 본인이 확인한 오류·수정 이유를 forms에 기록합니다.

## AI와 개발할 변경 과제

데이터 딕셔너리에 검사 장비 교정일과 교육용 기한을 정의하고 날짜 유효성·기한 초과 검증 규칙을 추가합니다. 실제 교정 규정을 추정하지 않습니다.

완성 프롬프트를 그대로 복사하는 대신 목표·자료·제약·필요 결과를 본인의 말로 요청합니다. 코드 작성·실행 오류 진단·테스트 설계·결과 설명에 AI를 사용할 수 있지만 최종 선택은 본인이 설명해야 합니다.


## 학습 활동

### 활동 1 — 분석 목표와 변경 계획을 먼저 정한다

원본 목표·기본 코드·데이터를 읽고 사용할 입력 시점과 평가 기준을 정리합니다. 현재 로트를 예측할 때 알 수 있는 필드는 무엇인가? 본인의 예상·미확인 사항을 forms에 적고 AI에 제공할 자료·코드 범위를 고릅니다.

### 활동 2 — 핵심 함수를 AI와 구현하고 첫 실행 결과를 보존한다

Colab에서 M01 구현 계약에 맞게 빈 함수를 작성하고 실행해 첫 결과와 그림을 보존합니다. AI와 설계·코드 변경을 진행합니다. 이번 변경 과제: 데이터 딕셔너리에 검사 장비 교정일과 교육용 기한을 정의하고 날짜 유효성·기한 초과 검증 규칙을 추가합니다. 실제 교정 규정을 추정하지 않습니다. 최초 코드와 실제 대화를 보존합니다.

### 활동 3 — 수정 코드를 실행하고 근거를 검증한다

변경한 소스를 저장하고 재실행합니다. 가상 재고번호의 전체 형식과 NIIN 부분을 어떻게 구분할까? AI의 주장·구현 선택 3건 이상을 원본·코드·검증 결과와 대조하고 보완을 요청합니다. 목표 미달·예시·교육용 가정·실측을 구분합니다.

### 활동 4 — 결과와 판단을 제출하고 다음 단계에 연결한다

변경 전후 결과·검토·최종 선택 이유를 양식에 정리합니다. 코드·노트북·로그·그림·보고서와 각 원본 산출물을 보존합니다. 개인 작성 완료와 실제 교관 승인 상태를 구분합니다.
