교육용 가상 로트의 규격·구매요구·납기·수령검사 정보를 분석하여 품질 위험을 경보합니다. 모든 업체 V01~V12, 로트, FSC·NIIN 형식, 검사관 INS-1~INS-4, 단가와 측정치는 가상입니다. 위험 지수는 판단 보조이고 최종 합부 판정은 사람이 합니다. 실제 업체 제재·군수 판정·행정 조치에 적용하지 않습니다.

## 파일과 진행 순서

1. lesson에서 원본 미션과 제공 자료를 읽고 forms 복사본 한 곳에서 작성합니다. M01~M10 순서로 진행합니다. 원본 코드들은 독립 실행되어 가상 데이터를 각각 생성합니다. seed42의 같은 기본 데이터로도 미션마다 다른 정제·격리·평가 범위를 쓰므로 수치의 범위를 먼저 확인합니다.
2. `QLT02_student_20261104v1.ipynb`를 Colab에 열고 `QLT02_실습프로젝트_20261104v1.zip`을 업로드합니다. 첫 셀에서 압축 해제 경로를 지정하고 준비 셀을 실행합니다. 상세 절차는 코랩 실행 안내를 따릅니다.
3. 제공 src에는 미션별 핵심 함수가 비어 있습니다. 먼저 Notebook의 구현 계약과 빈 함수를 AI와 완성해야 실행할 수 있습니다. 이후 각 미션의 변경 과제·AI 검토·수정 코드·전후 비교가 있어야 실습을 수행한 것입니다. 다른 자료를 만들거나 처음부터 모든 코드를 다시 작성할 필요는 없습니다.
4. 코드 변경 전 사본과 최초 AI 응답을 보존합니다. AI에 필요한 자료·목표·제약·결과 형식을 본인의 말로 요청하고 3개 설명/코드 선택을 근거·실행 결과와 대조합니다. AI 답변이 옳으면 유지 이유를 적습니다. 다시 ‘맞니?’라고 묻는 것만으로 검증되지 않습니다.
5. notebook 실행 셀은 모듈 실행 로그·그림·표를 미션별 outputs 아래 저장합니다. 기존 실행 기록을 지우지 않고 새 버전으로 비교합니다. 변경한 소스 코드와 forms 최종 기록도 제출합니다.
6. 마지막 셀은 docs/reports/양식·코드·출력 등을 `uploads/QLT02.zip`으로 묶습니다. 패키지 생성 자체가 정량 목표 달성이나 교관 승인은 아닙니다.

## 평가와 비교

원본 필수는 M1·M2·M3·M5·M7·M9·M10의7개이고 M4·M6·M8은 선택입니다. 이번 완성 실습에서는 지원 기능과 검증 경험을 위해10개를 모두 진행합니다. 원본 선택 여부는 본문에 유지하고, 수행하는 미션의 정량·정성·진행/완료3항목은 모두 평가합니다. 전체사이클은10개입니다.

평가는 Why〔왜 맡겼는가〕, How〔실제 AI 대화·코드 변경·자료/실행 대조〕, What〔본인의 최종 선택·전후 결과·반영 위치〕를 원본 정량·정성 기준과 함께 확인합니다. 기준값을 채우려고 평가 구간·분모·정답을 바꾸지 않습니다.

원본 예상은 28.5시간, CMS 정수 편성은 31시간입니다. 실제 학습 소요시간과 구분합니다. 난수시드가 같아도 라이브러리·플랫폼 차이로 소수값이나 실행시간은 달라질 수 있습니다. 원본 예시와 수정 참고풀이·본인 실행값을 구분합니다. 0건·기준0·미측정은 계산 불가/미실시와 이유를 표시합니다.

## 안전과 권한

실제 업체·계약·부대·장비 제원이나 민감정보를 AI에 넣지 않습니다. 촬영·녹음·실제 군수체계 연동을 하지 않습니다. AI 추천·기준 샘플링 결과·교육용 모의 판정·학습자 직접 입력·실제 검사관 승인을 구분합니다. 실제 승인 없이 검토 완료를 쓰지 않습니다.


## 처음 사용하는 용어

로트는 함께 검사할 물량 묶음, 필드는 표의 열, 피처는 예측에 넣는 특징입니다. Baseline은 비교용 기준 방법, hold-out은 학습에 쓰지 않고 평가하는 구간입니다. 정보 누수는 예측할 때 알 수 없는 결과를 입력에 섞는 오류입니다. 정답 점수를 맞추는 대신 실제 실행값과 이유를 기록하세요. 파이썬 기초는 필요하며 전문 군수 지식은 요구하지 않습니다.

## AI 질문과 기록

허용된 AI 서비스에 lesson의 해당 코드·입출력 계약·필요한 가상 자료만 붙입니다. 미션별 질문 예시를 자신의 질문으로 바꾸어 사용하세요. 답변의 주장 또는 코드 선택 3건 이상을 원문·테스트·실행값과 비교하고 채택·수정·보류 이유를 forms의 같은 미션에 적습니다. 실제 요청·답변 원문은 파일로 보존하고 경로를 적습니다. AI가 만든 성과나 승인은 쓰지 않습니다.

## 작성 파일을 여는 방법

Colab 왼쪽 파일 패널에서 QLT02_project/forms의 해당 양식과 docs/reports 문서를 엽니다. 파일을 수정한 뒤 저장하고 다운로드 사본을 보관합니다. 코드에는 Notebook의 replace_function 저장 셀을 사용합니다. ZIP 생성은 내용 평가나 교관 승인을 대신하지 않습니다. 기존 작업 폴더가 있으면 준비 셀은 이를 유지합니다. 새 배포본으로 바꾸려면 먼저 작업 ZIP을 내려받아 보관한 후 별도 작업 폴더에서 시작하세요.
