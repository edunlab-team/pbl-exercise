# QLT02 M10 군수품 수령 검사 불량 패턴 분석 및 품질 조기경보 시스템 통합 패키지 완성

당신은 교육용 품질 데이터 분석 담당자입니다. 데이터 검증부터 재학습, 배포 판정, 월간 조기경보까지 이어지는 자동 재학습 파이프라인으로 품질 조기경보 시스템을 통합한다.

## 원본 기준

- 목표: 데이터 검증부터 재학습, 배포 판정, 월간 조기경보까지 이어지는 자동 재학습 파이프라인으로 품질 조기경보 시스템을 통합한다.
- 원본 예상 3.5시간〔CMS 편성 4시간, 실측 시간이 아님〕
- 수행: 손상·중복 레코드를 격리하는 검증 단계, 피처 생성, 분포 변화(PSI) 점검을 거쳐 도전 모델을 재학습한다. 최근 3개월 hold-out에서 현행 모델과 MAE·R2·경보 재현율을 비교하는 배포 게이트로 배포 여부를 정하고, 최신 월 조기경보와 고위험 업체를 출력한다. 자체 점검표, 운영 가이드 목차, 브리핑 요약을 정리한다.
- 원본 평가: [필수] 통합 실행·자체 점검  — 자동 재학습 파이프라인이 오류 없이 실행되고 배포 게이트 판정이 기록되며, 자체 점검 전 항목 PASS, 운영 가이드 100% 완비, 브리핑 요약이 실행 결과와 일치하는가.
- 산출물: `docs/qlt02_operations_guide.md`, `pipeline/qlt02_retrain.py`, `QLT02.zip`

## 제공 자료와 코드

교육용 기본 코드 `pipeline/qlt02_retrain.py`와 공통 데이터 파일을 제공합니다. 핵심 함수는 학습자가 구현할 빈칸이며 나머지는 교육용 제공 도구입니다. 이 ZIP에는 source_originals 폴더나 교관 정답이 포함되어 있지 않습니다. 데이터 딕셔너리와 입력 예시는 실습프로젝트 data 폴더에 있습니다. 가상 데이터 생성식은 교육용 제공 도구입니다.

- 원본 가이드의 진행: 1) M10 코드를 실행해 데이터 검증 격리 결과와 PSI 분포 변화를 확인한다.
2) 모델 레지스트리와 배포 게이트 판정을 확인한다.
3) 최신 월 조기경보, 자체 점검표, 브리핑 요약 수치를 대조한다.
- 실제 성과값은 본인이 코드를 실행한 뒤 기록합니다. 미리 제시된 예시 수치를 본인 결과로 복사하지 않습니다.

## 출제자가 보완한 판단 기준

배포 게이트 통과와 새 모델 배포는 구분합니다. 기준에 못 미치면 기존 모델 유지가 정상 실행 결과일 수 있습니다. 참고 코드는 운영 가이드 목차만 출력하므로 학습자가 실제 본문 7개 장을 작성해야 합니다. 제공 pipeline/run_all.py는 M1~M10 실행·로그·그림·요약을 연결하는 교육용 실행 도구입니다. 독립적으로 가상 데이터를 만드는 원본 코드들을 실제 운영 DB·자동 배포 서비스로 통합했다고 주장하지 않습니다. 최신 월 경보는 과거 자료 재생 결과이며 새 모델을 고른 평가 구간과 분리한 미래 검증은 아직 없습니다. 자체 점검의 7개 항목과 문서 완비·정합성 확인을 별도로 평가합니다.

## 이번 미션의 구현 범위

- 파일: `pipeline/qlt02_retrain.py`
- 구현할 함수: `psi`
- 입력·출력 계약: a,b,bins → PSI 실수. 기준 구간 분위수·빈 구간 보정으로 분포 변화를 비교한다.
- 데이터 생성·공통 보조 함수는 제공 코드입니다. 반복되는 생성 함수 빈칸을 채우는 활동으로 대체하지 않습니다.
- 먼저 핵심 함수를 구현해 첫 실행 결과를 확보하고, 아래 변경 과제로 수정 전후를 비교합니다. 실제 AI 요청·답변과 본인이 확인한 오류·수정 이유를 forms에 기록합니다.

## AI와 개발할 변경 과제

기본 R2 배포 기준 0.85와 강화 가정 0.95를 별도 실험으로 비교합니다. 원래 평가 기준과 기본 판정은 유지하고, 강화 가정의 게이트·기존 모델 유지 결과를 구분해 기록합니다. 실제 본문 운영 가이드를 완성합니다.

완성 프롬프트를 그대로 복사하는 대신 목표·자료·제약·필요 결과를 본인의 말로 요청합니다. 코드 작성·실행 오류 진단·테스트 설계·결과 설명에 AI를 사용할 수 있지만 최종 선택은 본인이 설명해야 합니다.


## 학습 활동

### 활동 1 — 분석 목표와 변경 계획을 먼저 정한다

원본 목표·기본 코드·데이터를 읽고 사용할 입력 시점과 평가 기준을 정리합니다. 새 모델이 유지되면 파이프라인이 실패한 것인가? 본인의 예상·미확인 사항을 forms에 적고 AI에 제공할 자료·코드 범위를 고릅니다.

### 활동 2 — 핵심 함수를 AI와 구현하고 첫 실행 결과를 보존한다

Colab에서 M10 구현 계약에 맞게 빈 함수를 작성하고 실행해 첫 결과와 그림을 보존합니다. AI와 설계·코드 변경을 진행합니다. 이번 변경 과제: 기본 R2 배포 기준 0.85와 강화 가정 0.95를 별도 실험으로 비교합니다. 원래 평가 기준과 기본 판정은 유지하고, 강화 가정의 게이트·기존 모델 유지 결과를 구분해 기록합니다. 실제 본문 운영 가이드를 완성합니다. 최초 코드와 실제 대화를 보존합니다.

### 활동 3 — 수정 코드를 실행하고 근거를 검증한다

변경한 소스를 저장하고 재실행합니다. 목차 출력과 운영 가이드 완성은 어떻게 다른가? AI의 주장·구현 선택 3건 이상을 원본·코드·검증 결과와 대조하고 보완을 요청합니다. 목표 미달·예시·교육용 가정·실측을 구분합니다.

### 활동 4 — 결과와 판단을 제출하고 다음 단계에 연결한다

변경 전후 결과·검토·최종 선택 이유를 양식에 정리합니다. 코드·노트북·로그·그림·보고서와 각 원본 산출물을 보존합니다. 개인 작성 완료와 실제 교관 승인 상태를 구분합니다.
